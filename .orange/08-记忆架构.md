# 08 记忆架构

## 概览对比

| 维度 | deer-flow | hermes-agent | nanobot |
|------|-----------|--------------|---------|
| **记忆形态** | 结构化 JSON Facts | Markdown 文件（MEMORY.md/USER.md）| Markdown 文件（同上）|
| **会话内记忆** | LangGraph messages（append reducer）| SQLite messages 表 | session.json messages 数组 |
| **跨会话记忆** | Facts JSON + 分类摘要字段 | MEMORY.md + USER.md 文件 | MEMORY.md + USER.md 文件 |
| **记忆更新方式** | LLM 异步批量更新（MemoryUpdater） | Agent 主动调用 memory_tool | Dream 两阶段（定时执行）|
| **记忆注入时机** | 系统提示（每轮重建）| 系统提示快照（会话启动时一次性加载）| 系统提示（每轮重建）|
| **历史压缩** | DeerFlowSummarizationMiddleware | 上下文压缩（parent_session_id 链）| Consolidator（token 预算触发）|
| **持久化格式** | JSON 文件（原子写） | SQLite WAL | JSON 文件（原子写）|
| **外部 provider** | 无 | Honcho（可选插件）| 无 |

## deer-flow：结构化 Facts 记忆

### 数据结构

```python
# agents/memory/storage.py
memory_data = {
    "version": "1.0",
    "lastUpdated": "2026-05-08T10:00:00Z",
    "user": {
        "workContext":    {"summary": "正在开发 Python 爬虫", "updatedAt": "..."},
        "personalContext": {"summary": "偏好简洁风格", "updatedAt": "..."},
        "topOfMind":      {"summary": "本周 deadline：周五", "updatedAt": "..."},
    },
    "history": {
        "recentMonths":       {"summary": "过去三个月项目摘要", "updatedAt": "..."},
        "earlierContext":     {"summary": "更早期背景", "updatedAt": "..."},
        "longTermBackground": {"summary": "长期背景知识", "updatedAt": "..."},
    },
    "facts": [
        {
            "id": "fact_a1b2c3d4",
            "content": "User prefers Python for scripting",
            "category": "preference",  # preference|knowledge|context|behavior|goal|correction
            "confidence": 0.92,
            "createdAt": "2026-05-01T...",
            "source": "<thread_id>",
        },
        {
            "id": "fact_e5f6g7h8",
            "content": "User mistakenly said X, actually Y",
            "category": "correction",
            "confidence": 0.95,
            "sourceError": "X",   # correction 类别记录原始错误
        }
    ]
}
```

**六个事实类别：**

| 类别 | 含义 |
|------|------|
| `preference` | 用户偏好（工具、语言、风格）|
| `knowledge` | 用户的知识/技能水平 |
| `context` | 当前项目/任务上下文 |
| `behavior` | 用户的行为模式 |
| `goal` | 用户的目标/计划 |
| `correction` | 纠错记录（记住用户的误解以避免重复）|

### 记忆更新流程（异步）

```
每轮对话结束后
   │
   ▼
MemoryMiddleware.after_agent()
   │  将对话记录推入防抖队列（MemoryUpdateQueue）
   ▼
MemoryUpdateQueue
   │  每个 thread_id 独立去重，防止同一会话并发触发多次更新
   │  debounce_seconds: 默认 2 秒
   ▼
后台线程 MemoryUpdater.update(thread_id, conversation_transcript)
   │
   ▼
调用 LLM（MEMORY_UPDATE_PROMPT）
   │  输入：当前 memory JSON + 本轮对话内容
   │  要求输出：
   │    - 哪些摘要字段需要更新（shouldUpdate: true）
   │    - 新增事实列表（newFacts）
   │    - 要删除的事实 ID（factsToRemove）
   ▼
_apply_updates() 合并更新
   │  ├── confidence < 0.7（可配置）→ 丢弃
   │  ├── 重复内容检测（case-folded 比对）→ 跳过
   │  ├── facts 总量超过 max_facts（默认 100）→ 淘汰低置信度条目
   │  └── 上传文件路径 → 正则过滤，不持久化临时事件
   ▼
原子写入（.tmp → os.replace）
```

### 注入系统提示

```python
# agents/lead_agent/prompt.py - format_memory_for_injection()

# 按置信度降序排列
sorted_facts = sorted(facts, key=lambda f: f["confidence"], reverse=True)

injected = []
total_tokens = 0
for fact in sorted_facts:
    line = fact["content"]
    if fact["category"] == "correction":
        line += f"  (avoid: {fact['sourceError']})"
    line_tokens = estimate_tokens(line)
    if total_tokens + line_tokens > max_injection_tokens:  # 默认 2000 tokens
        break
    injected.append(line)
    total_tokens += line_tokens

# 包裹在 <memory> 标签内注入系统提示
return "<memory>\n" + "\n".join(injected) + "\n</memory>"
```

**关键设计：** token 预算控制 + 置信度优先级，确保最重要的记忆进入上下文窗口。

## hermes-agent：文件记忆 + SQLite 存储

### 两个记忆文件

```
~/.hermes/memories/
├── MEMORY.md   # Agent 自身知识笔记（工具特性、项目约定、环境事实）
└── USER.md     # 用户画像（偏好、沟通风格、背景）
```

**分隔符：** 文件内使用 `\n§\n`（节号）分隔独立条目，而非 Markdown 节标题。

**字符限制：**
- `MEMORY.md`：2200 字符
- `USER.md`：1375 字符

**四种操作：**

```python
# tools/memory_tool.py
def memory(action: str, content: str, target: str = "memory"):
    # action = "add"     → 追加一条新记录
    # action = "replace" → 子串匹配替换（不需要精确全文匹配）
    # action = "remove"  → 子串匹配删除
    # action = "read"    → 返回当前内容
```

### 快照加载机制（前缀缓存保护）

```python
# run_agent.py

# 会话启动时（第一次调用时）加载快照
if self._cached_system_prompt is None:
    if stored_prompt:
        # 继续旧会话 → 重用完全相同的系统提示，保持 Anthropic 前缀缓存命中
        self._cached_system_prompt = stored_prompt
    else:
        # 新会话 → 现在读取 MEMORY.md/USER.md 构建系统提示
        self._cached_system_prompt = self._build_system_prompt(system_message)

# 后续每轮对话复用同一个 _cached_system_prompt
```

**关键权衡：** 中途对 MEMORY.md 的写入不影响当前会话（快照已固定），但对 Anthropic 的前缀缓存非常友好，大量节省重复 token 费用。

### 记忆提供者架构（MemoryManager）

```python
# agent/memory_manager.py
class MemoryManager:
    _providers: list[MemoryProvider]   # 始终有 builtin，最多一个 external

    def prefetch_all(self, user_msg: str) -> str:
        """轮次开始前：从所有 provider 召回相关上下文"""

    def sync_all(self, user_msg: str, assistant_resp: str) -> None:
        """轮次结束后：向所有 provider 持久化本轮内容"""

    def queue_prefetch_all(self, user_msg: str) -> None:
        """为下一轮预热：后台异步召回"""

    def on_delegation(self, task: str, result: str, ...) -> None:
        """子 Agent 完成通知：外部 provider 可据此更新记忆"""
```

**MemoryProvider 抽象（可插拔）：**

```python
# agent/memory_provider.py
class MemoryProvider(ABC):
    @abstractmethod
    def recall(self, query: str) -> str: ...        # 召回相关记忆

    @abstractmethod
    def sync(self, user: str, assistant: str): ...  # 持久化对话

    @abstractmethod
    def on_delegation(self, task, result, **kwargs): ...
```

当前已实现：
- `BuiltinMemoryProvider`：基于 MEMORY.md/USER.md 文件
- `HonchoMemoryProvider`（可选 external）：Honcho 云记忆服务

### Nudge 机制（主动记忆提醒）

Agent 不会自动更新记忆——需要定期提醒才会主动调用 `memory` 工具：

```python
# 每 N 轮对话（默认 10）提醒 Agent 回顾 MEMORY.md
self._memory_nudge_interval = config.memory.nudge_interval   # 默认 10
self._turns_since_memory = 0

# 每 N 次工具调用（默认 10）提醒 Agent 考虑创建技能
self._skill_nudge_interval = config.memory.creation_nudge_interval   # 默认 15

# 触发后：在主响应完成后，后台异步启动 review agent
self._spawn_background_review(
    review_memory=True,
    review_skills=True,
)
```

**后台 review 机制：** review 是独立的 Agent 运行（不打断当前对话），完成后将更新写入文件，供下次会话快照加载。

## nanobot：Dream 两阶段记忆系统

### 三层记忆架构

```
Layer 1：会话内（session.json）
  messages[] + last_consolidated 游标

Layer 2：历史归档（history.jsonl）
  LLM 生成的摘要条目，带 cursor 范围

Layer 3：长期记忆（文件系统）
  MEMORY.md / USER.md / SOUL.md / skills/*.md
```

### MemoryStore（文件 I/O 层）

```python
# agent/memory.py
class MemoryStore:
    workspace: Path   # ~/.nanobot/workspace/

    def read_memory(self) -> str          # MEMORY.md
    def write_memory(self, content: str)  # MEMORY.md（直接覆盖）
    def read_memory_with_age(self) -> str # MEMORY.md + git blame 行龄标注

    def read_history(self, since_cursor: int) -> list  # history.jsonl 切片
    def append_history(self, entry: dict)              # 追加一条摘要
    def get_cursor(self) -> int                        # 当前最新 cursor

    def git.auto_commit(self, msg: str) -> str  # 提交 workspace 到 git
```

### git blame 行龄标注（nanobot 独有）

```python
def read_memory_with_age(self) -> str:
    lines = self.read_memory().splitlines()
    annotated = []
    for line in lines:
        age_days = self.git.get_line_age(line)  # git blame 查询该行最后修改时间
        if age_days and age_days > 14:
            annotated.append(f"{line}   ← {age_days}d")
        else:
            annotated.append(line)
    return "\n".join(annotated)
```

**效果示例：**
```markdown
I prefer Python over JavaScript   ← 62d   # 62天前写入，可能已过时
User uses macOS with M2 chip                # 近期写入，保留
Working on a web scraper project  ← 31d   # 31天前
```

### Consolidator（轻量 token 压缩）

```python
# agent/memory.py
class Consolidator:
    async def maybe_consolidate(self, session: Session) -> bool:
        tokens = estimate_tokens(session.messages)
        budget = self.config.context_window

        if tokens < budget * self.config.consolidation_ratio:  # 默认 0.5
            return False  # 未达到阈值

        # 找到可以截断的边界（不截断工具调用中间）
        boundary = pick_consolidation_boundary(session.messages)

        # 调用 LLM 生成摘要
        summary = await self.provider.chat_with_retry(
            model=self.config.model,
            messages=session.messages[:boundary],
            system=render_template("agent/consolidator_archive.md"),
        )

        # 持久化摘要
        self.store.append_history({
            "cursor": self.store.get_cursor(),
            "timestamp": now_iso(),
            "content": summary.content,
        })

        session.last_consolidated = boundary
        return True
```

### Dream（两阶段深度记忆）

```python
# agent/memory.py
class Dream:
    interval_hours: float = 2.0

    async def run(self) -> bool:
        # ── Phase 1：纯分析（无工具调用）──────────────────────
        new_entries = self.store.read_history(since=self.store.get_dream_cursor())
        memory_with_age = self.store.read_memory_with_age()  # 带行龄

        phase1_result = await self.provider.chat_with_retry(
            model=self.config.model,
            messages=[{"role": "user", "content": phase1_prompt}],
            system=render_template("agent/dream_phase1.md"),
            tools=None,  # 纯分析，禁止工具调用
        )

        # ── Phase 2：执行（有 read_file/edit_file/write_file）──
        result = await self._runner.run(AgentRunSpec(
            system=render_template("agent/dream_phase2.md"),
            initial_messages=[{"role": "user", "content": phase2_prompt}],
            tools=[read_file_tool, edit_file_tool, write_file_tool],
            max_iterations=self.config.max_iterations,
        ))

        # ── Git 提交 ─────────────────────────────────────────
        self.store.git.auto_commit(f"dream: {now_str()}, {changes} change(s)")
        self.store.update_dream_cursor(self.store.get_cursor())
        return True
```

**为什么两阶段优于单阶段（直接更新）：**

| 对比项 | 单阶段 | 两阶段 |
|--------|--------|--------|
| 编辑精确度 | LLM 可能重写整个文件 | Phase 2 使用 edit_file 做精确 diff 式修改 |
| Git 历史 | 整文件替换，blame 失效 | 精确修改，blame 正常追踪行龄 |
| Token 消耗 | 单次大调用 | Phase 1 轻量，Phase 2 针对性更强 |
| 过时识别 | 无法区分新旧内容 | 行龄标注帮助 LLM 识别过时信息 |

## 横向对比：核心设计差异

### 记忆更新触发方式

| 项目 | 触发方式 | 是否自动 | 延迟 |
|------|----------|----------|------|
| deer-flow | 每轮对话后异步触发 | 全自动 | 几秒（防抖）|
| hermes-agent | Agent 主动调用 memory 工具 + Nudge 提醒 | 半自动 | 主动调用立即，Nudge 在响应后 |
| nanobot | Consolidator（token 触发）+ Dream（定时）| 全自动 | 立即 / 每 2 小时 |

### 记忆结构化程度

```
结构化 ◄──────────────────────────────► 非结构化
deer-flow          nanobot/hermes
(Facts JSON        (MEMORY.md 自由文本)
 置信度分类)
```

- **deer-flow** 的结构化优势：可以按置信度过滤、精确删除单条事实、记录纠错历史
- **nanobot/hermes** 的非结构化优势：Agent 可以用自然语言组织记忆，更灵活

### 前缀缓存保护策略

| 项目 | 策略 | 效果 |
|------|------|------|
| deer-flow | 每轮重建系统提示，但记忆段用 `<memory>` 独立缓存 | 部分缓存 |
| hermes-agent | 会话启动时快照，全程不变 | 最强缓存（整个系统提示命中）|
| nanobot | 每轮重建（包含 SOUL.md 等），对 Anthropic 设置 cache_control | 中等缓存 |
