# 14 如何评测

## 概览对比

| 维度 | deer-flow | hermes-agent | nanobot |
|------|-----------|--------------|---------||
| **评测框架** | pytest 组件测试 + 少量 live test | Atropos RL 框架 + Terminal-Bench 2 | pytest（少量）|
| **评测类型** | 单元/集成测试为主，无 task benchmark | 任务完成率 benchmark（pass/fail）| 代码正确性为主 |
| **测试规模** | 130+ 测试文件 | ~3000 个 pytest 用例 | 少量测试 |
| **benchmark 数据集** | 无专用数据集 | Terminal-Bench 2（NousResearch/terminal-bench-2）+ TBLite | 无 |
| **eval 环境隔离** | Docker/本地沙箱 | Modal 沙箱（远程）+ Docker | 无 |
| **并发评测** | 无 | 100 任务并行（tool_pool_size=128）| 无 |
| **评分维度** | 组件行为正确性 | 任务通过率（pass@1）| 无 |
| **RL 集成** | 无 | Atropos（GRPO/PPO 训练数据生成）| 无 |

## hermes-agent：Terminal-Bench 2 评测体系

hermes-agent 拥有三个项目中最完整的评测体系，与 RL 训练框架深度集成。

### 评测执行流程

```python
async def rollout_and_score_eval(self, task: Task) -> EvalResult:
    """单个任务的评测全流程"""

    # 1. 解析任务描述（HuggingFace 数据集格式）
    task_description = task.data["description"]
    docker_image = task.data.get("docker_image")

    # 2. 注册 Modal 沙箱（远程隔离执行环境）
    sandbox_id = await self.register_task_env_overrides(
        task_id=task.task_id,
        docker_image=docker_image,
    )

    # 3. 运行 Agent（HermesAgentLoop）
    agent_result = await self._run_agent(
        messages=[{"role": "user", "content": task_description}],
        task_id=task.task_id,
        available_tools=["terminal", "file_read", "file_write"],
    )

    # 4. 上传测试套件到沙箱
    await self._upload_test_suite(sandbox_id, task.data["tests"])

    # 5. 在沙箱中执行 test.sh
    test_output = await self._run_in_sandbox(
        sandbox_id=sandbox_id,
        command="bash test.sh",
        timeout=self.config.test_timeout,
    )

    # 6. 解析测试结果（二进制打分）
    passed = self._parse_test_result(test_output)
    score = 1.0 if passed else 0.0

    # 7. 记录评测日志
    await self.evaluate_log(task, agent_result, score)

    return EvalResult(
        task_id=task.task_id,
        score=score,
        agent_messages=agent_result.messages,
        reasoning_per_turn=agent_result.reasoning_per_turn,
    )
```

### 评分机制

**评分是二进制的（pass/fail）：**
- 分数 = **1.0**：所有测试通过（`test.sh` 退出码 0）
- 分数 = **0.0**：任何测试失败（非零退出码）

这与软件工程任务的真实评估对齐——代码要么正确工作，要么不正确。

### 聚合统计

```python
async def evaluate(self) -> EvalMetrics:
    results = await asyncio.gather(*[
        self.rollout_and_score_eval(task)
        for task in self.tasks
    ])

    overall_pass_rate = sum(r.score for r in results) / len(results)

    # 分类统计（按任务类别）
    by_category = {}
    for result in results:
        category = self._get_task_category(result.task_id)
        by_category.setdefault(category, []).append(result.score)

    # WandB 日志
    wandb.log({
        "eval/overall_pass_rate": overall_pass_rate,
        **{f"eval/{cat}_pass_rate": rate for cat, rate in category_pass_rates.items()},
    })
```

### AgentResult：评测数据载体

```python
# environments/agent_loop.py
@dataclass
class AgentResult:
    messages: list[dict]              # 完整对话历史（含工具调用）
    managed_state: dict | None        # vLLM token/logprob 数据（RL 训练用）
    turns_used: int                   # 实际使用轮次
    finished_naturally: bool          # True=自然结束，False=超出 max_turns
    reasoning_per_turn: list[str | None]  # 每轮 thinking 内容（评测推理质量）
    tool_errors: list[ToolError]      # 工具错误列表（评测错误模式）
```

`reasoning_per_turn` 允许研究者分析：
- Agent 在做困难任务时 thinking 内容的质量
- thinking 长度与任务通过率的相关性
- 不同 reasoning_effort 设置的效果对比

class TestMemoryUpdater:
    def test_fact_confidence_threshold(self):
        """低置信度事实不应被保存"""
        new_facts = [
            {"content": "User uses vim", "category": "preference", "confidence": 0.8},
            {"content": "User might use emacs", "category": "preference", "confidence": 0.5},
        ]

        assert len(result["facts"]) == 1   # 只保留 confidence >= 0.7 的

    def test_max_facts_eviction(self):
        """超过 max_facts 时淘汰最低置信度的事实"""
        many_facts_memory = memory_with_n_facts(100, confidence=0.8)
        new_fact = {"content": "New high priority fact", "confidence": 0.95}
        result = updater._apply_updates(many_facts_memory, {"newFacts": [new_fact]})
        assert len(result["facts"]) == 100  # 不超过上限

```python
# tests/test_harness_boundary.py
def test_harness_does_not_import_app():
    """deerflow.* 包不应导入 app.* 包（保持 harness 独立性）"""
    import importlib, sys, types

    spy = types.ModuleType("app")
    spy.imported = False

    def getattr_spy(name):
        spy.imported = True
        raise ImportError(f"Illegal import: app.{name}")

    sys.modules["app"] = spy
    importlib.import_module("deerflow.agents.lead_agent.agent")

    assert not spy.imported, "deerflow package illegally imported from app package"
```

## 横向对比：评测体系设计总结

### 评测成熟度对比

```
评测完整度 ─────────────────────────────────────►
nanobot              deer-flow              hermes-agent
(基础单测)           (组件覆盖全面)          (工业级 benchmark)
    ↑                    ↑                       ↑
  学习研究            工程质量保证            模型训练+评测一体
```

### 三种评测理念

**hermes-agent（评测即训练）：**
- Terminal-Bench 2 既是评测工具，也是 RL 训练数据来源
- `AgentResult.managed_state` 保留 token logprobs（GRPO 训练需要）
- `reasoning_per_turn` 记录推理链（研究 thinking 质量）
- 高并发（128 线程）支持大规模模型对比实验

**deer-flow（评测即文档）：**
- 每个组件有对应测试，测试即最佳实践示例
- 快照测试（系统提示）防止提示词无意间回归
- 架构边界测试保证代码组织不腐化
- live test 可选运行（需要真实配置），CI 默认跳过

**nanobot（评测即学习）：**
- 测试少但清晰，降低学习者的认知负担
- 核心算法（Consolidator、Dream 调度）有单元测试覆盖
- 无 benchmark，定位是让研究者自己扩展评测框架

### 通用评测维度建议

| 维度 | 评测方法 | 数据集 |
|------|----------|--------|
| 代码生成 | pass@k（单元测试通过率）| HumanEval、MBPP |
| 工具使用 | 工具调用精确率 + 任务完成率 | ToolBench、ToolEval |
| 多轮对话 | 意图追踪准确率、上下文一致性 | MT-Bench |
| 记忆能力 | 跨会话事实召回率 | 自定义：注入事实后跨轮查询 |
| 指令遵循 | 约束满足率 | IFEval |
| 长上下文 | 信息检索准确率 | LongBench、Ruler |
