# 05 数据流

## 单次对话完整请求链路

```
用户输入（CLI 终端 / Telegram / Discord / 任意渠道）
        ↓
[1] 入口处理
    CLI:     HermesCLI.process_input() → 斜杠命令检测
    Gateway: GatewayRunner.dispatch() → 路由到对应平台 handler
        ↓
[2] 会话状态加载
    SessionDB.get_messages_as_conversation(session_id)
    → 从 SQLite 读取历史消息（带时间戳）
        ↓
[3] 系统提示组装 PromptBuilder._build_system_prompt()
    ├── SOUL.md → Agent 角色/个性（若配置）
    ├── 平台 hint → 针对 telegram/cli/cron 的格式指导
    ├── MEMORY.md → Agent 的跨会话知识笔记（≤2200 字符）
    ├── USER.md → 用户画像（≤1375 字符）
    ├── <available_skills> → 技能目录（XML 格式，不含全文）
    ├── AGENTS.md / .hermes.md / .cursorrules → 上下文文件（若存在）
    └── Honcho 用户建模（可选外部 provider）
        ↓
[4] 记忆 Prefetch
    MemoryManager.prefetch_all(query=user_message)
    → 从各 provider 检索相关记忆
    → 注入 <memory-context> 隔离块（不影响 system prompt 的 cache）
        ↓
[5] Anthropic Prompt Caching 标记
    agent/prompt_caching.py → 在系统提示末尾设置 cache_control
    （确保系统提示在同会话内缓存命中）
        ↓
[6] 主 ReAct 循环（run_conversation）
    messages = [system_prompt, *history, user_msg]
    tools = model_tools.get_tool_definitions(enabled_toolsets)

    while api_call_count < max_iterations and budget.remaining > 0:
        │
        ├─ LLM API 调用（OpenAI 格式）
        │   response = client.chat.completions.create(
        │       model=model,
        │       messages=messages,
        │       tools=tool_schemas,
        │       stream=True,           # 流式输出
        │   )
        │
        ├─ 若无 tool_calls → final_response，退出循环
        │
        └─ 若有 tool_calls → 工具执行
                ↓
[7] 工具执行 _execute_tool_call_batch(tool_calls)
    ├─ 并行安全工具（web_search/read_file 等）
    │   → ThreadPoolExecutor 并发执行
    │
    └─ 串行工具（terminal/write_file/clarify 等）
        → 顺序执行
        ↓
[8] handle_function_call(name, args, task_id)
    ├─ pre_tool_call hook（插件拦截点）
    │
    ├─ Agent 级工具（直接由 AIAgent 处理）：
    │   todo         → 更新 self._todos
    │   memory       → 读写 MEMORY.md / USER.md
    │   session_search → SessionDB.fts5_search()
    │   delegate_task  → 创建子 AIAgent 实例
    │
    └─ 注册表工具 → registry.dispatch(name, args) → 工具 handler
        ↓
[9] 工具结果处理
    ├─ 正常结果 → messages.append(tool_result_message)
    │
    └─ 大结果（超 token 预算）→ maybe_persist_tool_result()
        → 写入临时文件 ~/.hermes/tool_results/{uuid}.txt
        → 注入文件路径引用替代全文
        ↓
[10] 上下文压缩检查
     if prompt_tokens >= threshold(0.50) × context_length:
         ContextCompressor.compress()
         → 保头（系统提示 + 前 N 条）
         → 保尾（最近 20 条）
         → 调用辅助模型（Gemini Flash）生成中间摘要
         → "[CONTEXT COMPACTION]..." 标记
        ↓
[11] 会话持久化
     SessionDB.append_message() → SQLite WAL
     （FTS5 虚拟表自动更新全文索引）
     SessionDB.update_token_counts() → 计费统计
     MemoryManager.sync_all() → 通知各 provider 同步
        ↓
[12] 响应投递
     CLI:     Rich 面板 + 流式 token 显示（逐字符）
     Gateway: platform_api.send/edit_message()
     ACP:     WebSocket 流
```

## 记忆更新流

```
会话结束 / nudge 触发
        ↓
MemoryManager.on_turn_end(messages)
        ↓
分析对话内容（轻量 LLM 调用）：
    → 提取新的事实 / 偏好 / 知识
    → 判断是否需要更新 MEMORY.md
    → 判断是否需要更新 USER.md
        ↓
若需要更新：
    memory_tool.write(section, content)
    → 读取现有 MEMORY.md
    → 更新/追加
    → 原子写入（temp file + rename）
        ↓
下次对话时，PromptBuilder 重新读取
    → 注入系统提示
```

## 子 Agent 委托流

```
Lead Agent 调用 delegate_task(task_description, tools, max_iterations)
        ↓
delegate_tool.py 创建子 AIAgent 实例：
    sub_agent = AIAgent(
        session_id=f"{parent_session_id}:child:{uuid}",
        model=parent_model,
        enabled_toolsets=["terminal", "file", "web"],  # 可配置
        max_iterations=50,  # 独立预算
    )
        ↓
若 batch=True → ThreadPoolExecutor 并行（最多 3 个）
若 batch=False → 直接 await
        ↓
子 Agent 执行：
    → 独立会话 ID（不继承父消息历史）
    → 使用指定工具集
    → 完成后返回结果字符串
        ↓
Lead Agent 收到 delegate_task 工具结果
    → 汇总所有子 Agent 结果
    → 生成最终响应
        ↓
MemoryManager.on_delegation(results)
    → 通知记忆 provider 子任务完成
```

## 定时任务执行流

```
用户添加 cron 任务：
    /cron add "每天上午9点 检查邮件"
    → LLM 解析自然语言 → cron 表达式
    → cron/jobs.py 保存到 ~/.hermes/cron/jobs.json
        ↓
Cron scheduler（每 60 秒 tick()）：
    → 检查 jobs.json 中到期的任务
    → 创建 AIAgent 实例
    → 以 cron 格式提示运行（platform hint: "cron"）
    → 执行任务
        ↓
任务完成后：
    → 通过配置的渠道发送结果（Telegram / Email / ...）
    → 更新任务的 last_run 时间
```

## FTS5 历史搜索流

```
用户对话中 Agent 需要搜索历史记忆：
    tool_call: session_search(query="AWS pricing discussion")
        ↓
SessionDB.fts5_search(query, limit=10)
    → SQLite FTS5 全文搜索（BM25 排序）
    → 匹配所有历史会话的消息
    → 返回最相关的片段
        ↓
若结果太长 → auxiliary_client.summarize(results)
    → Gemini Flash 生成摘要
        ↓
工具结果返回给 Agent
    → Agent 利用历史信息继续对话
```

## 错误恢复流

```
LLM API 调用失败（rate limit / 网络）
    → tenacity 重试（指数退避）
    → 超过重试上限 → IterationBudget 标记错误
    → 用户收到友好提示

工具执行异常
    → 异常捕获，转为 tool_result(error=True, content="Error: ...")
    → 注入消息历史（Agent 决定下一步）

上下文超限（超过模型限制）
    → 尝试 ContextCompressor 压缩
    → 若还超 → 截断最早的消息
    → 继续执行

子 Agent 超时
    → ThreadPoolExecutor 取消任务
    → 返回 "Task timed out" 结果
    → Lead Agent 处理并说明失败原因
```
